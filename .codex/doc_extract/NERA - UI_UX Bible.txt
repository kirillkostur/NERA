NERA — UI/UX Bible
АКТУАЛЬНОЕ УТОЧНЕНИЕ: Translation-раздел, Translation Level и интерфейс постепенного перевода исключены. Terminal отображает Research, Library и открытые функции без отдельного Translation UI; см. «NERA — Current Scope Decisions», DD-001.
Назначение документа
UI/UX Bible описывает правила пользовательского интерфейса и взаимодействия игрока с системами NERA.
Этот документ не описывает техническую реализацию UI, конкретные prefab-структуры, код, шрифты или финальные макеты экранов.
Его задача — ответить на вопросы:
Как игрок понимает состояние станции?
Как игрок выбирает экспедиции?
Как работает терминал?
Как показываются дрон, лаборатория, библиотека и карта?
Как игрок читает древние записи?
Как отображается частичный перевод?
Как устроен инвентарь?
Как показываются аномальные слоты?
Как игрок получает уведомления?
Как UI поддерживает главный игровой цикл?

01. UI/UX Vision
Назначение главы
Эта глава фиксирует главную идею интерфейса NERA.
Главная идея
UI в NERA — это не просто набор меню.
UI является инструментом исследования.
Через интерфейс игрок:
понимает состояние станции;
выбирает следующую экспедицию;
запускает дрон;
получает результаты исследований;
читает записи;
видит прогресс перевода;
работает с библиотекой;
управляет инвентарём;
понимает состояние энергии;
принимает финальное решение.
Интерфейс должен помогать игроку отвечать на три вопроса:
Что я нашёл?
Что я теперь понимаю?
Куда мне идти дальше?
Главный UX-принцип
UI должен поддерживать основной цикл NERA:
экспедиция
↓
находка
↓
возвращение на станцию
↓
исследование
↓
понимание
↓
новая цель
Игрок не должен чувствовать, что он просто открывает меню.
Он должен чувствовать, что работает с исследовательским инструментом.
Главная мысль главы
UI NERA должен помогать игроку превращать неизвестное в знание.
02. Главные UX-принципы
Принцип 1. UI должен быть понятным с первого взгляда
Игрок должен быстро понимать:
что доступно;
что заблокировано;
что требует энергии;
что требует исследования;
что уже изучено;
что ещё непонятно;
куда можно отправиться.
Принцип 2. Минимум лишней информации
NERA не должна перегружать игрока таблицами, сложными параметрами и лишними цифрами.
Лучше показывать:
статус;
смысл;
причину;
следующее действие.
Не нужно превращать UI в инженерную панель с десятками параметров.
Принцип 3. Интерфейс должен объяснять причину недоступности
Если игрок не может что-то сделать, UI должен объяснить почему.
Примеры:
Недостаточно энергии.
Дрон заряжается.
Антенна не восстановлена.
Исследование уже выполняется.
Запись пока невозможно перевести.
Нет свободного аномального слота.
Предмет отсутствует в инвентаре или хранилище.
Принцип 4. UI должен отличать знание от действия
В NERA есть два типа интерфейсной информации:
действие — запустить дрон, начать исследование, выбрать экспедицию;
знание — прочитать запись, увидеть перевод, понять результат анализа.
Эти вещи нельзя смешивать в кашу.
Принцип 5. UI должен поддерживать атмосферу
Интерфейс должен выглядеть как часть исследовательской программы NERA.
Он должен быть:
тёмным;
техническим;
циановым;
читаемым;
чистым;
функциональным;
без лишнего декоративного шума.
Главная мысль главы
UI должен быть не красивым сам по себе, а полезным, атмосферным и читаемым.
03. HUD
Назначение главы
Эта глава описывает интерфейс во время обычного управления персонажем.
Главная идея
HUD должен быть минимальным.
NERA не должна постоянно показывать игроку большое количество интерфейсных элементов.
На экране должны быть только те элементы, которые нужны в текущий момент.
Что может быть в HUD
HUD может показывать:
здоровье;
стамину;
активный быстрый слот;
краткое уведомление;
подсказку взаимодействия;
состояние опасности;
минимальную информацию о текущей цели выхода.
Что не должно постоянно висеть на HUD
Не нужно постоянно показывать:
полный инвентарь;
все ресурсы;
все задачи;
большую карту;
все параметры станции;
длинные сообщения;
постоянный список квестов.
Главная мысль главы
HUD должен освобождать экран для мира, а не закрывать его.
04. Interaction UI
Назначение главы
Эта глава описывает UI взаимодействия с объектами мира.
Главная идея
Interaction UI должен быть простым и контекстным.
Игрок смотрит на объект и видит доступное действие.
Примеры:
Press E — Interact
Hold E — Repair
Press E — Pick Up
Press E — Open
Press E — Use Terminal
Hold E — Clean Panel
Недоступное действие
Если действие недоступно, UI должен показывать причину.
Примеры:
Недостаточно энергии.
Нужна деталь.
Объект повреждён.
Сначала запустите терминал.
Нет свободного слота.
Нужен исследованный кристалл.
Long Interaction
Для удержания кнопки нужен простой progress indicator.
Используется для:
ремонта;
чистки;
подключения;
перезапуска;
открытия тяжёлого механизма;
других долгих действий.
Главная мысль главы
Interaction UI должен отвечать на вопрос: что я могу сделать с этим объектом прямо сейчас?
05. Inventory UI
Назначение главы
Эта глава описывает интерфейс инвентаря.
Главная идея
Инвентарь должен быть простым, читаемым и разделённым на логические зоны.
У игрока есть:
3 быстрых слота / инструмента;
5 / 10 / 15 слотов рюкзака;
3 аномальных слота.
Открытие инвентаря
Инвентарь открывается отдельной кнопкой в любой момент.
Мир при этом не ставится на паузу.
Это важно, потому что игрок должен понимать:
инвентарь — это физическое действие в опасном мире;
в экспедиции нельзя бесконечно безопасно разбирать предметы;
выбор момента для открытия инвентаря имеет значение.
Структура экрана
Инвентарь должен визуально разделять:
быстрые слоты;
рюкзак;
аномальные слоты;
описание выбранного предмета;
доступные действия.
Примерная логика:
[Quick Slots]
[Backpack Slots]
[Anomaly Slots]
[Item Details]
Быстрые слоты
Быстрые слоты используются для инструментов и быстрого доступа.
Они должны быть видны яснее, чем обычный рюкзак.
Рюкзак
Рюкзак хранит обычные предметы.
Размер рюкзака может увеличиваться:
5 слотов;
10 слотов;
15 слотов.
Один предмет занимает один слот.
Действия с предметами
В зависимости от типа предмета UI может давать действия:
осмотреть;
выбросить;
переместить;
поместить в хранилище;
использовать;
поместить в аномальный слот;
прочитать;
отправить на исследование.
Не все действия доступны всегда.
Главная мысль главы
Inventory UI должен быть не складом с кучей ресурсов, а простым инструментом управления найденными объектами.
06. Anomaly Slots UI
Назначение главы
Эта глава описывает отображение аномальных слотов.
Главная идея
Аномальные слоты — отдельная зона инвентаря для изученных кристаллов и аномальных объектов.
Они не являются обычными слотами рюкзака.
Количество
У игрока есть:
3 аномальных слота
Что показывает слот
Каждый слот должен показывать:
пустой слот;
установленный кристалл;
цвет / тип кристалла;
статус изучения;
доступное свойство;
расходуется ли кристалл при использовании.
Неизученный кристалл
Неизученный кристалл нельзя полноценно использовать.
UI должен объяснять:
Сначала исследуйте кристалл в лаборатории.
Изученный кристалл
Для изученного кристалла UI показывает понятное свойство.
Пример:
Короткий энергетический импульс.
Активирует древние устройства.
Нестабилен. Расходуется после применения.
Главная мысль главы
Anomaly Slots UI должен ясно показывать, какие аномальные возможности игрок взял с собой в экспедицию.
07. Station Terminal UX
Назначение главы
Эта глава описывает главный интерфейс станции.
Главная идея
Станционный терминал — главный UI-хаб NERA.
Игрок подходит к физическому терминалу, нажимает взаимодействие, после чего открывается полноценный UI.
Терминал не является полностью diegetic-экраном, где игрок должен читать мелкие элементы в 3D-мире.
Решение:
3D-терминал в мире
↓
Press E
↓
полноэкранный UI терминала
Роль терминала
Через терминал игрок управляет:
картой экспедиций;
дроном;
статусом станции;
энергией;
апгрейдами;
лабораторией;
библиотекой;
переводом записей;
антенной;
статусами систем.
Основная структура терминала
Рекомендуемые разделы:
Map / Expeditions
Drone
Station Status
Energy
Upgrades
Research
Library
Translation
Antenna / Signals
Главный экран терминала
Главный экран должен показывать краткое состояние:
доступные экспедиции;
статус дрона;
активное исследование;
состояние энергии;
новые записи;
новые переводы;
важные предупреждения станции.
Что терминал не должен делать
Терминал не должен быть перегруженной панелью администратора.
Он не должен показывать все данные всех систем одновременно.
Главная мысль главы
Терминал — это рабочее место игрока, где он превращает хаос экспедиций в понятный следующий шаг.
08. Expedition Map UI
Назначение главы
Эта глава описывает экран карты экспедиций.
Главная идея
Карта экспедиций должна быть комбинацией карты и списка / карточки выбранной локации.
Рекомендуемая структура:
левая / центральная часть — карта;
правая часть — карточка выбранной точки;
нижняя часть — действия.
Типы точек на карте
На карте должны ясно различаться:
обычные экспедиции;
? точки;
станция;
недоступные зоны;
зоны, ожидающие данных дрона;
точки с новыми данными.
Обычная экспедиция
Обычная экспедиция — это локация цивилизации NERA, открытая дроном.
Она может иметь карточку:
название / рабочее название;
статус;
краткое описание;
уровень опасности;
наличие новых данных;
кнопка отправиться.
? точка
? точка связана с человеческими следами, предыдущими экспедициями или сигналами.
Она должна визуально отличаться от обычной экспедиции.
Карточка может показывать:
Unknown Signal
Signal Type: Human / Damaged / Weak
Source: Unknown
Status: Not Investigated
Состояния точки
Точка на карте может быть:
не открыта;
обнаружена;
доступна;
исследована;
частично исследована;
требует события;
опасная;
завершена.
Главная мысль главы
Карта должна не просто показывать куда идти, а объяснять тип цели: это объект NERA или человеческий след?
09. Drone Control UI
Назначение главы
Эта глава описывает интерфейс управления дроном.
Главная идея
Drone UI должен показывать, что дрон — инструмент разведки, который открывает новые экспедиции.
Состояния дрона
UI должен показывать:
недоступен;
повреждён;
восстановлен;
заряжается;
готов к запуску;
в полёте;
вернулся;
данные доступны;
требуется разгрузка.
Запуск дрона
Экран должен показывать:
готовность дрона;
радиус разведки;
ожидаемое время;
возможный результат;
кнопку Launch.
Возвращение дрона
После возвращения дрона UI показывает:
новая экспедиция обнаружена;
данные карты обновлены;
возможная находка в cargo slot;
дрон разряжен и требует зарядки.
Ограничения
UI должен объяснять:
дрон уже в полёте;
дрон заряжается;
нет энергии;
буря / событие не позволяет запуск;
дрон не восстановлен.
Главная мысль главы
Drone UI должен делать открытие новых локаций понятным и ожидаемым.
10. Energy Status UI
Назначение главы
Эта глава описывает отображение энергии станции.
Главная идея
Energy UI должен быть простым.
Игроку не нужно видеть сложную электросеть.
Он должен понимать:
сколько энергии есть;
что потребляет энергию;
что отключено;
почему система не работает;
что можно выключить.
Основные элементы
Energy UI может показывать:
текущий заряд батарей;
производство энергии;
потребление энергии;
основные потребители;
системы включены / выключены;
предупреждения.
Power Manager
Power Manager позволяет игроку включать и отключать некоторые системы.
Примеры:
наружный свет;
теплица / декоративный модуль, если нужен;
турель;
антенна;
лаборатория;
дрон-станция;
часть освещения.
Главное ограничение
Energy UI не должен превращаться в Factorio.
Игрок не должен настраивать сложные цепи, линии, напряжение и приоритеты.
Главная мысль главы
Energy UI должен отвечать на вопрос: почему станция работает или не работает прямо сейчас?
11. Station Status UI
Назначение главы
Эта глава описывает экран общего состояния станции.
Главная идея
Station Status UI показывает игроку, какие системы станции работают, требуют внимания или недоступны.
Состояния систем
Система может быть:
offline;
online;
damaged;
service required;
disabled by power;
upgrade available;
locked;
working.
Что показывает экран
Station Status может включать:
терминал;
солнечные панели;
батареи;
турели;
дрон;
антенну;
лабораторию;
хранилище;
наружные системы.
Attention Required
Отдельно можно показывать блок:
Attention Required
Туда попадают:
солнечные панели загрязнены;
дрон вернулся;
исследование завершено;
недостаточно энергии;
турель требует перезапуска;
антенна повреждена;
новая запись доступна.
Главная мысль главы
Station Status UI должен быстро показывать, что требует внимания, а что работает нормально.
12. Research UI
Назначение главы
Эта глава описывает экран исследования.
Главная идея
Research UI должен ощущаться как научный анализ, а не как крафт.
Правильная логика:
Unknown Object
↓
Analysis
↓
New Understanding
Неправильная логика:
Item + Time = Reward
Основной экран
Research UI должен показывать:
доступные объекты для анализа;
активное исследование;
время до завершения;
краткое описание объекта;
предполагаемый тип;
результат после завершения;
историю завершённых исследований.
Один анализ за раз
Лаборатория выполняет одно исследование за раз.
Если исследование уже идёт, UI должен показывать:
Analysis in Progress
Результат исследования
После завершения UI показывает:
новую запись в библиотеке;
свойство кристалла;
часть понимания языка;
данные об IO;
подсказку к древнему устройству;
новый нарративный фрагмент.
Главная мысль главы
Research UI должен давать игроку ощущение, что он не просто перерабатывает предметы, а понимает неизвестное.
13. Library UI
Назначение главы
Эта глава описывает интерфейс библиотеки.
Главная идея
Библиотека — это место, где хранится знание игрока.
Она должна быть комбинацией категорий и карточек.
Категории библиотеки
Рекомендуемые категории:
Ancient Records
Research Notes
IO
Artifacts
Human Logs
Translation Database
Station Data
Карточка записи
Карточка может содержать:
название;
категорию;
статус понимания;
короткое описание;
полный текст;
перевод;
связанные объекты;
дату / фазу нахождения;
статус: new / updated / complete.
Обновление старых записей
Если после новых исследований старая запись переводится лучше, библиотека должна показать, что она обновлена.
Пример:
Ancient Record 03 — Updated
Главная мысль главы
Библиотека должна быть не складом текста, а живым архивом понимания.
14. Language Translation UI
Назначение главы
Эта глава описывает экран перевода древних записей.
Главная идея
Language Translation UI — один из ключевых интерфейсов NERA.
Он должен показывать, как неизвестный язык постепенно становится понятным.
Структура экрана
Экран перевода может показывать:
оригинальный древний текст;
текущий перевод;
неизвестные фрагменты;
уровень понимания;
известные смысловые концепты;
кнопку Translate / Re-Analyze;
статус обновления.
Уровни перевода
NERA использует уровни понимания, а не проценты.
Рекомендуемые уровни:
Unknown
Fragmented
Partial
Stable
Complete
Пример
Unknown
⟟⍜ ⌇⟒⏁ ⎍⋔⏚⍀⏃ ⍙⟒⍀⟒ ⌇⟟☌⋏⏃⌰
Fragmented
[Unknown] signal detected near [Unknown].
Partial
Emergency signal detected near [Unknown] facility.
Stable
Emergency signal detected near the containment facility.
Complete
Emergency signal detected near the containment facility. The evacuation protocol has failed.
Обновление перевода
Когда игрок открывает новые смысловые концепты, старые записи могут стать понятнее.
UI должен показывать это как событие:
Translation Updated
Что нельзя делать
Не нужно показывать перевод как сухую математику.
Проценты вроде Translation 37% использовать не рекомендуется.
Уровни понимания выглядят атмосфернее и лучше поддерживают тайну.
Главная мысль главы
Перевод должен ощущаться как восстановление смысла, а не как заполнение прогресс-бара.
15. Communication / Antenna UI
Назначение главы
Эта глава описывает интерфейс антенны и сигналов.
Главная идея
Аntenna UI показывает неизвестные сигналы, в основном связанные с людьми, прошлыми экспедициями и ? точками.
Состояния антенны
Антенна может быть:
locked;
damaged;
offline;
online;
scanning;
signal detected;
signal investigated.
Сигналы
Сигнал может показывать:
тип сигнала;
силу сигнала;
примерное направление;
статус;
короткое описание;
кнопку Track / Mark.
Связь с картой
После обнаружения сигнала на карте появляется ?.
Это важно:
Antenna detects signal
↓
Map adds ?
Что означает ?
? — это не обычная экспедиция цивилизации NERA.
Это неизвестный сигнал, чаще всего связанный с людьми или прошлой миссией.
Главная мысль главы
Antenna UI добавляет человеческий слой мира через сигналы и следы прошлых экспедиций.
16. Notification UI
Назначение главы
Эта глава описывает короткие уведомления игрока.
Главная идея
Уведомления должны быть короткими, редкими и полезными.
Они не должны превращаться в поток сообщений.
Где отображаются
Уведомления появляются в верхней части HUD или в специальной небольшой зоне экрана.
Типы уведомлений
Примеры:
Drone returned.
Research complete.
New translation available.
Station power low.
Solar panels dirty.
Turret requires service.
Signal detected.
World event incoming.
Правила
одно уведомление за раз;
очередь уведомлений;
не спамить одинаковым событием;
показывать только важное;
детали — в терминале.
Главная мысль главы
Notification UI должен сообщать игроку “что важно сейчас”, но не заменять терминал.
17. Death / Failure / Return UI
Назначение главы
Эта глава описывает интерфейс смерти, провала или возвращения.
Главная идея
Смерть и провал не должны выглядеть как аркадный game over.
UI должен быть сдержанным и атмосферным.
Возможные состояния
player died;
expedition failed;
return to station;
load last save;
critical item secured;
data lost / data retained;
Возвращение из экспедиции
После успешного возвращения можно показывать краткое summary:
Items recovered
Records found
Research objects collected
Crystals collected
New data available
Главное ограничение
Не превращать возвращение в экран наград как в лутере.
Summary должен быть функциональным, а не праздничным.
Главная мысль главы
Failure / Return UI должен поддерживать тон NERA: спокойно, серьёзно, функционально.
18. UI Visual Style
Назначение главы
Эта глава описывает общий визуальный стиль интерфейса.
Главная идея
UI должен быть тёмным, технологичным и циановым.
Образ:
terminal interface;
holographic map;
thin cyan lines;
dark background;
clean panels;
sharp readable blocks;
minimal noise;
functional sci-fi.
Основные визуальные элементы
тонкие контуры;
циановые линии;
тёмные панели;
простая сетка;
малые индикаторы;
карточки;
технические подписи;
минимальная декоративность;
мягкое свечение.
Карта
Карта может использовать:
голографический вид;
контурные линии;
топографические формы;
световые точки;
сектора;
карточки локаций;
цветовые статусы.
Цветовая логика UI
циан — основной интерфейс;
белый — основной текст;
зелёный — рабочее состояние;
жёлтый — предупреждение;
красный — ошибка / опасность;
серый — недоступно;
синий — данные / анализ.
Что нельзя делать
Не нужно перегружать UI:
слишком большим количеством линий;
сложными декоративными рамками;
микротекстом;
постоянными анимациями;
слишком яркими цветами;
лишними sci-fi элементами без функции.
Главная мысль главы
UI должен выглядеть как рабочий исследовательский инструмент, а не как декоративная sci-fi заставка.
19. Финальный выбор UI
Назначение главы
Эта глава описывает финальный интерфейсный момент игры.
Главная идея
Перед финалом игрок получает выбор через терминал.
После прохождения финальной локации, возвращения на станцию, анализа документа и полного перевода сообщения игрок должен принять финальное действие.
Финальная ситуация
Игрок видит полное предупреждение древней цивилизации.
После этого терминал предлагает выбор:
Отправить данные на Землю
Выключить терминал
Смысл выбора
Этот выбор не должен быть обычной кнопкой “завершить игру”.
Он должен быть эмоциональным финальным действием.
Отправить данные на Землю
=
дать человечеству маленький шанс.
Выключить терминал
=
закрыть последний экран и оставить знание при себе / завершить без передачи.
После выбора
После выбора запускаются титры.
Важное правило
Передача данных на Землю не является регулярной игровой кнопкой на протяжении всей игры.
Она используется как финальное действие.
Главная мысль главы
Финальный UI должен превратить главное знание игры в последнее решение игрока.
20. What UI/UX Is Not
Назначение главы
Эта глава фиксирует, чем UI/UX NERA не должен становиться.
UI — не MMO-панель
Не нужно много постоянных иконок, статусов, квестов и списков.
UI — не инженерная таблица
NERA не должна показывать слишком много параметров энергии, станции и систем.
UI — не лутер-интерфейс
Инвентарь не должен превращаться в сетку с десятками мусорных предметов.
UI — не визуальный шум
Sci-fi UI не должен быть перегружен декоративными линиями, псевдотекстом и лишними анимациями.
UI — не отдельная игра
Перевод, исследование и терминал не должны превращаться в сложные мини-игры.
UI — не постоянный квестлог
Игра не должна вести игрока только списком задач.
Игрок должен ориентироваться через станцию, карту, находки и собственное любопытство.
Главная мысль главы
UI NERA должен быть инструментом понимания, а не слоем шума между игроком и миром.
Итоговая формула UI/UX Bible
Минимальный HUD
+
простое взаимодействие
+
читаемый инвентарь
+
полноэкранный терминал
+
карта + карточки локаций
+
дрон как инструмент открытия экспедиций
+
библиотека как архив знаний
+
перевод как восстановление смысла
+
уведомления только по важному
+
финальный выбор через терминал
Главная мысль документа
UI/UX NERA должен помогать игроку не просто управлять системами, а понимать мир.
Интерфейс должен превращать найденные фрагменты, записи, кристаллы и сигналы в ясное ощущение прогресса:
Я нашёл.
Я изучил.
Я понял.
Я готов идти дальше.
