NERA — Sprint 02 Plan
Station Power + Terminal Placeholder
1. Назначение Sprint 02
Sprint 02 нужен, чтобы впервые собрать рабочую станционную часть core loop.
После Sprint 02 игрок должен понимать:
“Я на сломанной станции. Я могу восстановить питание. После этого открывается терминал, и через него игра двигается дальше.”
Это ещё не полноценный терминал, не карта и не дрон. Это технический и геймплейный фундамент для них.
2. Главная цель спринта
Цель
Сделать первый рабочий сценарий на станции:
игрок появляется на станции;
терминал выключен;
рядом есть объект питания;
игрок взаимодействует с объектом питания;
питание станции включается;
меняется состояние станции;
терминал становится доступен;
игрок может открыть placeholder Terminal UI;
в терминале видит placeholder-действие “Launch Drone”;
действие пока не запускает полноценного дрона, но может показать debug-сообщение или открыть заглушку следующего шага.
3. Почему это важно
Sprint 01 проверяет:
ходьбу;
камеру;
взаимодействие;
смену сцен;
pickup;
технический билд.
Sprint 02 проверяет уже игровую причинно-следственную цепочку:
сломанная станция
→ взаимодействие
→ изменение состояния мира
→ открытие новой функции
→ доступ к терминалу
Это первая настоящая основа NERA.
4. Sprint 02 Scope
4.1. Что входит в Sprint 02
В Sprint 02 входит:
Station Power State;
объект питания на станции;
состояние “станция без энергии”;
состояние “станция с энергией”;
блокировка терминала без питания;
разблокировка терминала после включения питания;
placeholder Terminal UI;
placeholder Terminal navigation;
debug action “Launch Drone”;
сохранение состояния в рамках текущей игровой сессии;
минимальный visual feedback;
минимальный audio placeholder, если быстро;
технический тестовый билд.
4.2. Что НЕ входит в Sprint 02
В Sprint 02 не входит:
полноценная карта;
полноценный дрон;
открытие Expedition 01 через карту;
research system;
library system;
translation system;
save/load на диск;
полноценный UI style;
финальный art pass станции;
полноценный звук;
VFX pass;
IO;
анимации ремонта;
катсцены;
сложные туториалы.
5. Игровой сценарий Sprint 02
5.1. Начальное состояние
Когда игрок запускает сцену Station_FirstPlayable, станция находится в состоянии:
StationPowerState = Offline
Игрок видит:
тусклое освещение;
неактивный терминал;
объект питания / power core / fuse box;
interaction prompt у объекта питания;
interaction prompt у терминала, но терминал сообщает, что нет питания.
5.2. Взаимодействие с терминалом до питания
Если игрок подходит к терминалу до восстановления питания, он может получить prompt:
[E] Use Terminal
После нажатия:
Terminal Offline
Restore station power first.
Терминал не открывает полноценный UI.
5.3. Взаимодействие с источником питания
Игрок подходит к объекту питания.
Prompt:
Hold [E] Restore Power
После успешного удержания:
Station power restored.
Состояние меняется:
StationPowerState = Online
5.4. Состояние станции после включения питания
После включения питания:
включается свет;
терминал становится активным;
на терминале появляется экран / glow / emissive;
prompt терминала меняется;
игрок может открыть Terminal UI.
Минимально допустимо для Sprint 02:
включить 1–3 light object;
включить emissive material на терминале;
вывести debug text;
открыть placeholder UI.
5.5. Открытие терминала
Когда питание включено:
Prompt:
[E] Open Terminal
После нажатия открывается fullscreen UI:
NERA Station Terminal
Внутри видны placeholder-разделы:
Status
Map
Drone
Library
Research
Translation
Exit
На Sprint 02 интерактивным должен быть только минимальный раздел:
Drone → Launch Drone
5.6. Placeholder Launch Drone
При нажатии на “Launch Drone” пока не нужно запускать полноценного дрона.
Достаточно одного из вариантов:
Вариант А — debug message
Drone launch requested.
Expedition discovery system not implemented yet.
Вариант B — placeholder screen
Drone System
Status: Available
Action: Launch Drone
Result: Expedition 01 placeholder discovered.
Вариант C — сразу записать debug-состояние
Expedition_01_Unlocked = true
Для Sprint 02 лучше выбрать Вариант B + debug-состояние, потому что это подготовит Sprint 03.
6. Основные системы Sprint 02
6.1. Station Power System
Назначение
Хранит текущее состояние питания станции.
Минимальные состояния
Offline
Online
Возможные будущие состояния
Damaged
Partial
Online
Overloaded
Shutdown
Но для First Playable пока нужны только:
Offline
Online
6.2. Station Power Controller
Назначение
Главный контроллер питания станции в сцене.
Он должен:
знать текущее состояние питания;
принимать команду восстановления питания;
уведомлять другие объекты о смене состояния;
включать / выключать связанные объекты;
давать другим системам простой способ проверить, есть ли питание.
6.3. Power Restore Interaction
Назначение
Объект, с которым игрок взаимодействует, чтобы включить станцию.
Это может быть:
power core;
fuse box;
broken generator;
dirty power module;
emergency switch.
Для First Playable лучше использовать простой объект:
Station Power Core
6.4. Terminal Access Controller
Назначение
Проверяет, можно ли открыть терминал.
Правило:
если StationPowerState = Offline → терминал не открывается
если StationPowerState = Online → терминал открывается
6.5. Terminal Placeholder UI
Назначение
Временный fullscreen UI, который показывает структуру будущего терминала.
Он не обязан быть красивым.
Главное:
открывается;
закрывается;
блокирует управление игроком;
показывает разделы;
имеет одну рабочую кнопку;
готов к расширению в следующих спринтах.
7. Правила реализации
7.1. Общие правила
Делать простую, расширяемую реализацию.
Не строить финальную архитектуру на 20 систем сразу.
Сейчас важнее:
работает → понятно → можно расширить
а не:
идеально → сложно → долго
7.2. Station Power Rules
Делать
хранить состояние питания в одном месте;
использовать enum для состояния;
уведомлять подписчиков через event;
давать публичное read-only свойство IsPowered;
делать простую ручную настройку через Inspector.
Не делать
не размазывать состояние питания по разным объектам;
не проверять питание через поиск объектов в сцене;
не завязывать терминал напрямую на конкретный power core;
не делать сложную систему электричества;
не делать распределение энергии по комнатам;
не делать power grid.
7.3. Terminal Rules
Делать
терминал должен проверять питание перед открытием;
UI терминала должен открываться fullscreen;
терминал должен закрываться по кнопке Esc или Back;
управление игроком должно отключаться, пока терминал открыт;
курсор мыши должен включаться в Terminal UI.
Не делать
не делать финальный дизайн терминала;
не делать полноценную карту;
не делать сложную навигацию;
не делать research/library/translation внутри Sprint 02;
не смешивать terminal logic и station power logic.
7.4. Interaction Rules
Делать
использовать уже созданную систему Interaction из Sprint 01;
Power Restore должен быть hold interaction;
Terminal Open должен быть press interaction;
prompt должен меняться в зависимости от состояния.
Не делать
не писать отдельный interaction system только для питания;
не использовать hardcoded input внутри каждого объекта;
не делать ремонт через отдельную механику.

11. Состояния станции
11.1. Offline
Состояние по умолчанию.
StationPowerState = Offline
Активно:
слабый аварийный свет;
power core interactable;
terminal locked;
terminal offline prompt;
переход в экспедицию можно оставить доступным для debug, но не считать частью финального flow.
Неактивно:
terminal UI;
drone action;
online lights;
station systems.
11.2. Online
Состояние после восстановления питания.
StationPowerState = Online
Активно:
normal station lights;
terminal screen;
terminal prompt;
terminal UI;
drone placeholder action.
Неактивно:
restore power interaction;
offline-only feedback;
offline terminal message.

13. Input Rules
13.1. Gameplay Mode
Когда терминал закрыт:
Player movement = enabled
Camera control = enabled
Cursor = hidden
Cursor lock = locked
Gameplay input = enabled
UI input = disabled / limited
13.2. Terminal Mode
Когда терминал открыт:
Player movement = disabled
Camera control = disabled
Cursor = visible
Cursor lock = unlocked
Gameplay input = disabled
UI input = enabled
13.3. Exit Terminal
Терминал закрывается через:
Esc
Close Button
Back action
После закрытия:
Player movement = enabled
Camera control = enabled
Cursor = hidden
Cursor lock = locked

15. Критерии готовности Sprint 02
Sprint 02 считается готовым, если:
15.1. Station Power
сцена стартует с выключенной станцией;
есть объект питания;
игрок может подойти к объекту;
появляется hold prompt;
после удержания питание включается;
состояние станции меняется;
повторно включить питание нельзя или не нужно.
15.2. Terminal
до включения питания терминал не открывается;
терминал показывает сообщение, что нужно восстановить питание;
после включения питания терминал открывается;
терминал открывается fullscreen;
терминал закрывается;
при открытом терминале игрок не двигается;
после закрытия терминала управление возвращается.
15.3. UI
UI терминала виден;
есть список основных разделов;
есть placeholder Drone section;
есть button Launch Drone;
нажатие Launch Drone даёт понятный debug result.
15.4. Technical
нет ошибок в Console;
сцена запускается напрямую;
билд собирается;
билд запускается;
игрок может пройти сценарий без Editor-only действий.

18. Риски Sprint 02
18.1. Риск: уйти в сложный UI
Проблема:
Можно потратить много времени на красивый терминал.
Решение:
UI должен быть серым, простым, техническим.
Главная цель — logic flow.
18.2. Риск: начать делать полноценного дрона
Проблема:
Drone system может раздуть Sprint 02.
Решение:
В Sprint 02 только placeholder.
Настоящий дрон — Sprint 03.
18.3. Риск: усложнить power system
Проблема:
Можно начать делать генераторы, кабели, предохранители, комнаты, нагрузку.
Решение:
В First Playable питание — это один boolean/enum state.
18.4. Риск: забыть про build
Проблема:
В Editor всё работает, а в билде ломается input/cursor/UI.
Решение:
В конце Sprint 02 обязательно standalone build.
