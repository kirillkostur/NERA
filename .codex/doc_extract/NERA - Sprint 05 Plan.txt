NERA — Sprint 05 Plan
Research + Library Placeholder
1. Назначение Sprint 05
Sprint 05 нужен, чтобы после первой экспедиции у игрока появился смысл возвращения на станцию.
После Sprint 04 игрок уже может:
Station
→ Restore Power
→ Launch Drone
→ Discover Expedition 01
→ Travel to Expedition 01
→ Find Ancient Record
→ Inspect NERA Memory Core
→ Notice IO Trace
→ Return to Station
Sprint 05 добавляет следующий шаг:
Return to Station
→ Analyze Research Object
→ Update Library
→ Improve Translation Level
→ Receive hint for next goal
Главная задача Sprint 05 — впервые показать центральную тему игры:
Понять важнее, чем победить.
2. Главная цель спринта
Цель
Сделать первый рабочий placeholder research flow.
Игрок должен:
вернуться на станцию после Expedition 01;
открыть терминал;
увидеть, что есть новый объект для анализа;
запустить research / analysis;
получить результат анализа;
увидеть обновление Library;
увидеть улучшение Translation Level;
получить намёк на следующую цель.
3. Почему это важно
До Sprint 05 находки в экспедиции существуют только как flags:
AncientRecord01_Found = true
ResearchObject01_Collected = true
IOTrace01_Seen = true
Но для NERA этого мало.
Игра должна объяснить игроку:
Я не просто подобрал объект.
Я получил данные.
Станция их обработала.
Теперь я лучше понимаю NERA.
Sprint 05 превращает находки в знание.

6.1. Назначение
Research System отвечает за обработку найденных объектов.
Она не должна быть просто inventory.
Её смысл:
найденный объект
→ анализ
→ результат
→ новое знание
→ обновление библиотеки
→ прогресс понимания

Состояния:

6.4. Research rules
Делать
хранить состояние research object отдельно от UI;
запускать анализ через терминал;
после анализа обновлять Library;
после анализа обновлять Translation;
показывать понятный результат игроку.
Не делать
не делать research tree;
не делать ресурсы для анализа;
не делать длинные таймеры;
не делать crafting;
не делать upgrade system;
не смешивать research с inventory UI;
не открывать новую локацию напрямую через research.

23. Риски Sprint 05
23.1. Риск: сделать слишком большую Library
Проблема:
Библиотека может быстро превратиться в отдельную игру с кучей категорий и текстов.
Решение:
В Sprint 05 только 3–4 записи.
Главная задача — проверить unlock и отображение.
23.2. Риск: сделать полноценную Translation System
Проблема:
Можно уйти в проценты, словарь, мини-игру и сложные правила перевода.
Решение:
Только уровни:
Unknown / Fragmented / Partial / Stable / Complete.
В Sprint 05 используется только Unknown → Fragmented.
23.3. Риск: открыть Expedition 02 слишком рано
Проблема:
Research result может случайно стать unlock-кнопкой новой локации.
Решение:
Research даёт hint.
Drone открывает обычные экспедиции.
23.4. Риск: смешать Research, Library и Translation
Проблема:
Один UI-скрипт начинает хранить всё: объект, анализ, записи, перевод.
Решение:
ResearchController анализирует.
LibraryController открывает записи.
TranslationController меняет уровень.
Terminal UI только показывает.
