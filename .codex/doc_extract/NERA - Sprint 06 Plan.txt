NERA — Sprint 06 Plan
First Playable Integration + Save Placeholder
1. Назначение Sprint 06
Sprint 06 нужен, чтобы собрать все сделанные системы в один стабильный First Playable flow.
До этого спринты добавляли отдельные куски:
Sprint 01 → player / camera / interaction / scene transitions
Sprint 02 → station power / terminal placeholder
Sprint 03 → drone / expedition unlock
Sprint 04 → Expedition 01 content
Sprint 05 → research / library / translation placeholder
Sprint 06 не должен добавлять много нового контента.
Его задача:
собрать всё вместе
→ проверить полный проход
→ убрать критические debug-зависимости
→ добавить минимальный save placeholder
→ подготовить First Playable к дальнейшему polish
2. Главная цель спринта
Цель
Сделать стабильный полный проход First Playable от старта до получения намёка на следующую цель.
Игрок должен пройти:
Start on Station
→ Restore Power
→ Open Terminal
→ Launch Drone
→ Discover Expedition 01
→ Travel to Expedition 01
→ Find Ancient Record
→ Inspect NERA Memory Core
→ Notice IO Trace
→ Return to Station
→ Analyze NERA Memory Core
→ Library Updated
→ Translation Level: Fragmented
→ New Objective Hint
И всё это должно работать:
без ручных действий в Editor;
без debug-кнопок как обязательного шага;
без потери runtime state при смене сцен;
без ошибок в Console;
в standalone build.
3. Почему это важно
До Sprint 06 проект может работать кусками.
Например:
терминал работает отдельно
экспедиция работает отдельно
research работает отдельно
library работает отдельно
Но First Playable — это не набор систем.
First Playable — это проверка:
работает ли игра как единый опыт
Sprint 06 отвечает на главный вопрос:
Можно ли уже пройти NERA от начала до первого понимания?

6. Полный First Playable Flow
6.1. Flow Stage 01 — Station Offline
Начало игры:
Scene: Station_FirstPlayable
StationPowerState = Offline
Terminal = Locked
Drone = Locked
Expedition01 = Unknown
Игрок должен:
появиться на станции;
увидеть, что станция не работает;
найти power core;
восстановить питание.
Критерий:
игрок понимает: сначала нужно включить станцию
6.2. Flow Stage 02 — Station Online
После восстановления питания:
StationPowerState = Online
Terminal = Available
Drone = Ready
Игрок должен:
увидеть визуальную смену состояния станции;
открыть терминал;
перейти в Drone section.
Критерий:
игрок понимает: теперь можно использовать терминал
6.3. Flow Stage 03 — Drone Scan
В терминале:
DroneState = Ready
Игрок запускает дрон:
Launch Drone
→ DroneState = Scanning
→ Scan Complete
→ Expedition01 = Discovered
Критерий:
игрок понимает: дрон нашёл новую точку
6.4. Flow Stage 04 — Travel to Expedition 01
После сканирования:
Expedition01 = Discovered
Travel = Available
Игрок нажимает:
Travel
→ Load Expedition_01_FirstPlayable
Критерий:
переход в экспедицию происходит из терминала, а не через debug
6.5. Flow Stage 05 — Expedition 01
В экспедиции игрок должен:
появиться в правильной точке;
пройти короткий маршрут;
прочитать древнюю запись;
осмотреть NERA Memory Core;
заметить IO Trace;
вернуться на станцию.
Флаги:
Expedition01_Visited = true
AncientRecord01_Found = true
ResearchObject01_Collected = true
IOTrace01_Seen = true
Expedition01_Returned = true
Критерий:
игрок возвращается на станцию с данными
6.6. Flow Stage 06 — Research
После возврата:
ResearchObject01_Collected = true
ResearchObject01_Analyzed = false
Терминал показывает:
New object available:
NERA Memory Core
[Analyze]
После анализа:
ResearchObject01_Analyzed = true
Критерий:
игрок понимает: находку нужно анализировать на станции
6.7. Flow Stage 07 — Knowledge Update
После анализа:
Library entries unlocked
AncientLanguageLevel = Fragmented
NextObjectiveHintAvailable = true
Игрок видит:
обновление Library;
изменение Translation Level;
намёк на следующую цель.
Критерий:
игрок ощущает: я понял больше
7. GameSessionState
7.1. Назначение
GameSessionState — временное хранилище прогресса First Playable.
Он нужен, чтобы состояние не терялось между сценами.
Пример:
игрок нашёл объект в Expedition 01
→ вернулся на станцию
→ терминал должен знать, что объект найден
7.2. Что хранить в GameSessionState
Минимальный список:
StationPowerState
DroneState
Expedition01_State
Expedition01_Visited
AncientRecord01_Found
ResearchObject01_State
IOTrace01_Seen
Expedition01_Returned
LibraryEntry_NERA_MemoryCore_Unlocked
LibraryEntry_AncientOutpost_Unlocked
LibraryEntry_AncientLanguage_FirstSymbols_Unlocked
LibraryEntry_IO_WeakTrace_Unlocked
AncientLanguageLevel
NextObjectiveHintAvailable
7.3. Что НЕ хранить в GameSessionState
Не хранить:
ссылки на scene objects;
ссылки на UI buttons;
ссылки на GameObjects из сцен;
temporary VFX;
audio sources;
camera references;
loaded prefabs;
runtime-only interaction targets.
Плохо:
GameSessionState.TerminalButton = someButton;
Хорошо:
GameSessionState.ResearchObject01_State = Collected;
8. State Persistence Between Scenes
8.1. Проблема
При смене сцен Unity уничтожает объекты сцены.
Если состояние лежит на объекте сцены, оно потеряется.
Плохо:
AncientRecord01_Found хранится на AncientRecord_01 в Expedition scene
После возврата на станцию терминал может не знать, что запись найдена.
8.2. Решение для First Playable
Использовать один persistent object:
GameSession
Он создаётся при старте игры и не уничтожается при смене сцен.
Пример:
GameSession
├── GameSessionState
├── SceneFlowController
└── DebugSessionControls
8.3. Правило
Scene objects могут менять state.
Но scene objects не должны быть главным хранилищем прогресса.
Правильно:
AncientRecordInteractable
→ GameSessionState.AncientRecord01_Found = true
Неправильно:
AncientRecordInteractable.found = true
9. Save Placeholder
9.1. Назначение
Save Placeholder нужен не для финального сохранения игры.
Он нужен, чтобы заранее понять:
какие данные вообще нужно сохранять
9.2. Что сделать в Sprint 06
Минимальный вариант:
SaveData class
SaveDataMapper
Debug Save
Debug Load
Debug Reset
Это может работать:
в памяти;
через JSON в Application.persistentDataPath;
через временный editor-only debug.
Лучше для Sprint 06:
JSON save в Application.persistentDataPath
Почему:
быстро;
проверяет реальное сохранение;
работает в билде;
не требует сложной архитектуры.
9.3. Что сохранять
Сохранять только First Playable state:
StationPowerState
DroneState
Expedition01_State
Expedition01_Visited
AncientRecord01_Found
ResearchObject01_State
IOTrace01_Seen
Expedition01_Returned
Library entries
AncientLanguageLevel
NextObjectiveHintAvailable
9.4. Что не сохранять
Не сохранять:
позицию игрока;
точное состояние камеры;
открытый UI экран;
temporary prompts;
VFX state;
audio state;
progress bar сканирования;
состояние hold interaction;
ссылки на объекты.
Для First Playable достаточно сохранять этапы прогресса.
10. Save / Load Rules
10.1. Save
Save должен происходить вручную через debug-кнопку или debug hotkey.
Например:
F5 → Save
F9 → Load
F10 → Reset
Или через Debug panel.
10.2. Load
Load должен восстановить:
состояние станции;
открыта ли Expedition 01;
найдены ли объекты;
анализирован ли объект;
открыты ли записи Library;
Translation Level;
hint.
10.3. Reset
Reset должен вернуть First Playable в начальное состояние:
StationPowerState = Offline
DroneState = Locked
Expedition01 = Unknown
ResearchObject01 = NotFound
AncientLanguageLevel = Unknown
Library entries = locked
10.4. Не делать autosave
В Sprint 06 не делать autosave.
Почему:
сначала нужно проверить структуру данных
Autosave можно добавить позже.
11. Scene Bootstrap Rules
11.1. Назначение
Каждая сцена должна при загрузке синхронизироваться с GameSessionState.
Пример:
если StationPowerState = Online
→ станция должна визуально быть Online
→ терминал должен быть доступен
→ power core не должен снова предлагать Restore Power
11.2. Station Bootstrap
При загрузке станции:
Read GameSessionState
Apply station power visual state
Apply terminal access state
Apply drone state
Apply research availability
Apply library state
Apply translation state
Apply objective hint
11.3. Expedition Bootstrap
При загрузке Expedition 01:
Read GameSessionState
Mark Expedition01_Visited = true
Hide AncientRecord if already found
Hide / disable MemoryCore if already collected
Mark IOTrace if already seen
Setup return beacon
Set objective text

Debug_OpenResearchResult
Debug_SetLibraryEntry
Debug может ускорять тест.

14.4. Expeditions Section
Должен учитывать:
Expedition01_State
Возможные состояния:
Unknown → not shown / locked

Для First Playable достаточно:

Discovered
Returned
14.5. Research Section
Должен учитывать:
ResearchObject01_State
Состояния:
NotFound → No samples
Collected → Analyze available

14.6. Library Section
Должен показывать только unlocked entries.
Locked entries можно не показывать.
Для First Playable лучше:
показывать только то, что игрок уже открыл
14.7. Translation Section
Должен показывать:
AncientLanguageLevel
Без процентов.

23. Риски Sprint 06
23.1. Риск: начать переписывать архитектуру
Проблема:
Когда систем стало много, появляется желание всё переписать красиво.
Решение:
Не переписывать всё.
Стабилизировать только то, что нужно для First Playable.
23.2. Риск: сделать полноценный save
Проблема:
Save/load может разрастись в сложную систему.
Решение:
Только SaveData для First Playable.
Без slots, autosave, cloud, settings.
23.3. Риск: сломать scene transitions
Проблема:
Persistent GameSession, spawn ids и UI cursor могут конфликтовать.
Решение:
Проверять переходы после каждого изменения.
Не откладывать build test на самый конец.
23.4. Риск: debug останется частью прохождения
Проблема:
Системы могут работать только через debug-кнопки.
Решение:
В конце пройти игру с нуля без debug.
Debug оставить только для ускорения тестов.
